LangGraph: Python에서 구조를 얻는다

LangGraphAdapter.analyze()가 compiled graph의 Node와 conditional Edge를 읽습니다. __start__ / __end__ Node는 제외합니다.

LangFlow: Flow JSON에서 구조를 얻는다

LangFlowAdapter.analyze()가 /data/nodes와 /data/edges를 읽습니다. group_outputs=True 출력이 2개 이상인 Node를 Router로 보고 나가는 Edge를 Branch로 매핑합니다.

실행 시 공식 LFX 엔진은 flow.json의 내장 Component 코드를 사용합니다. 설명에 사용한 components.py의 7개 Custom Component 원문이 /data/nodes/<index>/data/node/template/code/value와 일치함을 확인했습니다. scripts/build_langflow.py가 이 JSON을 내보냅니다.

발견과 선언을 구분합니다
Node·Edge·Branch는 Adapter가 발견합니다. Tool Schema·Mock 결과·지식 문서·Capability·Failure Type·Probe·Coverage Target은 Manifest에서 선언됩니다. Tool 인수 / Probe를 코드와 대조한 설명은 이 자료의 검토 결과이며, Core가 임의 코드의 업무 의미를 증명한 결과는 아닙니다. LangFlow Router 인식도 현재 Adapter의 출력 메타데이터 규칙입니다. Sample의 RAG 응답은 검색된 문서 content를 직접 반환하며, 실제 LLM 추론은 평가 Judge에서 사용합니다. confidence=1은 명시적 Owner 계약의 기본 메타데이터이며 통계적으로 보정된 신뢰 확률이 아닙니다.

05 / ACTUAL UI SNAPSHOTS
코드의 근거가 UI에서 어떻게 보이는가
실행 중인 평가 스튜디오에서 촬영한 실제 화면 10개입니다. 이미지를 누르면 확대됩니다. 운영 후보 수는 반복 데모가 누적된 현재 Draft 수이며 기본 Manifest 사례 수와 다릅니다. 캡처 과정에서 등록·생성·저장·평가를 새로 실행하지 않았습니다.


06 / RESULTS & LIMITS
PASS / HOLD와 Coverage를 읽는 방법
같은 오류 질문에 서로 다른 기대 계약이 있습니다
definition_hr-error는 expected_status=error와 안내 문구를 요구하므로 예외 처리 시 PASS입니다. 운영 실패에서 승인한 복구 사례는 expected_status=ok와 ‘남은 연차’ 응답을 요구합니다. Agent가 계속 오류를 내면 이 계약은 FAIL이고 HR Golden v3는 HOLD입니다. 평균 Quality가 높아도 통과로 표시하지 않습니다.


Coverage는 설계된 평가 대상의 범위입니다
inventory(spec)의 분모와 Case의 targets의 교집합을 계산합니다. Branch Target이 덮였다고 실제 분기 실행이 검증되었다는 뜻은 아닙니다. 운영 질문은 관찰된 scenario_id 집합을 사용하고 미래 전체는 unknown입니다.
실패 분모는 선언된 failure_types와 관찰된 failure_type의 합집합입니다. 예를 들어 execution_error가 tool_failure와 별도 항목으로 추가됩니다.
Coverage 원문
판정과 지표의 정확한 범위
Overall Score는 모든 Quality Evaluator 점수의 단순 평균입니다. 사례마다 함수 개수가 다르면 사례별 평균의 평균과 다릅니다. Gate 점수는 평균에서 제외됩니다.
Gate 실패, Evaluator 실행 오류 또는 Quality threshold 실패가 있으면 최종 HOLD입니다. PASS는 모든 적용된 평가가 통과했을 때만 표시합니다.
RAG Probe는 경로/문서 검사, 문서 사례는 Exact/Recall/Faithfulness 검사로 구분합니다. Faithfulness는 실제 소형 LLM의 미보정 판정입니다. 한국어 이유를 요청해도 모델이 영문으로 답하면 원문을 보존합니다.
Tool Schema 선언과 tool_call 인수 검사는 구분됩니다. Timeout Simulation과 latency 제한도 별도입니다. 함수별 정확한 검사 범위는 위 평가 함수 설명에서 확인하세요.
